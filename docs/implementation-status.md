Known boundaries: one local user/service, Claude model/API harness outside the native Bash sandbox; Bash fixture restrictions verified; full-harness containment unverified, no OAuth or public deployment, no automatic merge, no native subagents, and no token-budget support. Runtime session files must be preserved alongside worktrees. SDK costs missing from interrupted turns cannot be accounted for exactly by this service.

The native CLI reported a usable local login. Authenticated Claude tasks were verified without reading or copying credential values or account details. See [live verification evidence](live-claude-verification.json).

Earlier local verification: 23 tests passed, TypeScript checks pass for server and UI, and the production build succeeds. The built stdio proxy was exercised against the authenticated HTTP service. Generated patches passed `git apply --check` against the primary repository. Browser fixture evidence is saved in `docs/console-preview.png`.

MCP Events implementation adds the official MCP 2.0 HTTP transport while retaining legacy tool clients. Modern discovery, event operations, tools, and UI resources were exercised on one authenticated endpoint. Subscriptions and delivery queues persist; production callbacks validate public DNS addresses and pin connections for TLS. Host registration and actual ChatGPT reception remain unverified.

Latest verification: all 101 tests pass, server and UI TypeScript checks pass, and the production build succeeds. Settings tests cover persistence, ownership, partial updates, invalid-update atomicity, task overrides, and native MCP discovery/envelopes. Host form tests cover HTTP multi-round-trip delegation, repeated submissions, argument binding, ownership, expiration, questions and multiple selections, stale responses, permission defaults, and cancellation. Browser verification confirms the delegation form selects the effective default worker. Webhook tests use injected callbacks and transport doubles; they do not establish external host delivery or contact real callback endpoints.

Codex session tests inject the HTTP transport of the official OpenAI SDK. They verify actual request serialization, ownership/workspace binding, subscribe-before-input ordering, coordinator turn termination, and cancellation acknowledgement. They make no model calls and do not prove backend idempotency or executor isolation. The adapter requires an explicit model and creates no turn before the executor and session state can be persisted. It is available only through explicit service opt-in configuration.

The macOS executor foundation has actual local sandbox tests for file access, read-only writes, symlink escape, Git metadata protection, denied direct network access and permitted proxy-port connections. The installed native Codex CLI starts under this profile. The authenticated CONNECT proxy allows only documented executor hosts and rejects private or mixed DNS results before pinning an address. Proxy tests use local listeners and injected DNS/dial functions; they contact no external host. Native authenticated proxy compatibility remains unverified. Process-group shutdown is tested, but descendants that escape the group are not proven terminated. The executor is wired into the opt-in Codex provider; its sandbox does not protect Claude tasks.

Executor lifecycle coordination now shares concurrent startup, binds identity and policy, retains compute between turns, excludes concurrent turn writers, and waits for startup during explicit shutdown. Failure remains observable and prevents fresh work during shutdown. Native cancellation confirmation retrieves the selected coordinator turn and rechecks session ownership/workspace; terminal turn state and quiescent session state are both required, with timeout or caller abort leaving termination unconfirmed. Tests cover cancellation racing completion, initial idle state, wrong-session/subagent targets, failed startup, active leases and shutdown failures. The active coordinator is in memory; launch reservations and process mapping now persist through the executor journal. Recovery of surviving owned process groups is verified locally, including startup reservations without a saved PID.

Provider-aware cost budgets now reject unsupported numeric limits before persistence, execution or continuation. Explicit null is preserved through owner defaults, task overrides, host forms, and the browser form, and omits the Claude SDK cost ceiling. Runtime limits remain mandatory. The existing $5 default remains. Tests verify unlimited execution, settings persistence, continuation rejection, native Claude configuration, and host-form defaults. Browser fixture verification confirms the cost checkbox disables the amount field and the completed task displays No cost limit. This prepares Codex budget gating but does not enable its provider.

Native Codex provider orchestration now covers explicit execution-turn permission, persist-before-start ordering, native SDK streaming and question handlers, selected coordinator tracking, strict saved-result validation and awaited executor shutdown. Numeric cost and token budgets are rejected. Whole-turn permission is explicit; this adapter does not provide individual shell-command approvals. Unconfirmed termination leaves a durable waiting task, locks controls and defers artifacts rather than claiming cancellation. The provider is explicitly opt-in. Recovery restores an interrupted task only after local shutdown and remote coordinator termination are confirmed; unknown outcomes remain locked. Authenticated verification remains pending.

Durable executor records now reserve launches before spawning, bind PID updates to a unique launch, and prevent replacement until a confirmed stop. Owner, workspace, policy and session identities are validated; remote URL values are hashed rather than stored. Native recovery checks local state before confirming the coordinator turn. Uncertain records and unknown input outcomes remain locked, including when the native provider is unavailable. Actual local process tests verify journal integration and process-group disappearance after stop; stale PID recovery never signals the stored PID. Service configuration requires explicit opt-in, model, absolute executable and distinct application/executor keys, and fixture-only mode excludes live providers. Provider resources close before SQLite, and recovery runs before HTTP serving. Surviving executor recovery now checks the unique launch marker, process birth time, user and group before each signal, waits for group disappearance, and persists the confirmed stop. Real-process tests cover reopening the journal while an executor survives, including the startup gap before its PID was saved. Identity changes, reused PIDs, legacy records without fingerprints, ambiguous launches and live groups without their leader remain locked. Real account permissions, authenticated execution and termination of descendants that escape the group remain unverified.

Task handoff now offers a reviewable, editable message with the task ID, bounded task/result excerpts and tool references for full evidence. Standalone Copy for Codex was exercised in the live browser fixture console; embedded Send to conversation uses the portable MCP App message method after explicit submission, reports host rejection, and remains unverified in an actual host. Codex execution permissions now describe whole-turn shell authority in both console and host forms, with deny selected by default. A native HTTP form test verifies disclosure, policy visibility and approval binding. The provider status label identifies Codex separately from Claude.

Queued human-input cancellation now rejects promptly when its provider or task signal aborts, including signals already aborted before publication. The queue preserves predecessor ordering even when a middle request is cancelled. A regression test holds the first permission open, cancels the second, verifies the third cannot bypass it, rejects a stale first response, and confirms neither cancelled request appears in durable input events. This prevents publishing an unanswerable permission after its provider turn has ended.

Artifact deep links now select the referenced artifact rather than only opening the artifact tab. The selected view provides a return to all artifacts, and missing IDs show an explicit unavailable state. Selecting an artifact publishes its task ID, artifact ID and bounded title through portable model context; selecting another task clears artifact context. Browser fixture checks verified a real report URL, list/reopen navigation and a missing artifact ID. Type checking and the production build passed after this UI change; the last full backend suite remains 98 passing tests.

Service tokens, other-provider keys, SSH agent access, cloud credentials, Node preload settings and inherited proxy credentials are excluded. A test intercepts the installed SDK's real spawn callback, verifies the generated native runtime environment using synthetic credentials, and refuses startup before any process or model call. The full suite now passes 99 tests with no skips; type checking and the build pass. This filters environment inheritance only: Claude's own authentication remains available to the harness, and approved shell commands still execute without an OS sandbox. Filesystem, keychain and network access are not contained by this change.

Claude now requires its installed SDK's native Bash sandbox, with fail-if-unavailable enabled, automatic Bash approval disabled, unsandboxed retries disabled, no excluded commands and no weaker isolation options. The policy configures no allowed outbound domains or Unix sockets/local listeners, allows writes to the canonical worktree, denies Git metadata writes, and denies reads of the home/repository/sibling-worktree regions with explicit worktree and Git read exceptions. Native Read/Edit/Write hooks and human Bash approval remain in place. A real SDK spawn-boundary test checks the serialized settings before refusing any process/model call. All 100 tests pass with no skips, along with type checking and the build. Actual Bash enforcement and tool compatibility still require authenticated Claude verification. The native sandbox covers Bash and its descendants, not the model/API harness or every native tool; it is not full-worker containment.
