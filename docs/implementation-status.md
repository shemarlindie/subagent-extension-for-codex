Known boundaries: one local user/service. By default a Claude task has the same authority as the user's Claude Code CLI: no extension sandbox, all tools and subagents, the user's permission mode, and repository `.claude/settings.json` files applied. The optional extension sandbox covers Bash only; the model/API harness stays outside it, and full-harness containment is unverified. No service OAuth or public deployment, no automatic merge, and no token-budget support. Runtime session files must be preserved alongside worktrees. An interrupted turn reports no cost of its own; a later turn that resumes the session reports it with its own, but one that doesn't leaves it uncounted.

Authenticated Claude tasks were verified with the configured Claude Code credentials, without reading or copying credential values or account details. See [live verification evidence](live-claude-verification.json).

Budget enforcement happens at response boundaries, so a response can exceed the configured amount; it is not a hard billing cap. Every scenario was rerun on October 7, 2026 under the CLI parity defaults with plain replies; the resume scenario continues through a follow-up message. Parity covered a project skill, a project MCP server, a subagent and a project hook.

Use `npm run typecheck` and `npm test` for current validation.
